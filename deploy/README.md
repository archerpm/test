# Выкладка на VPS в Москве (одна команда)

Результат: сайт на вашем сервере (данные остаются в РФ), заголовки безопасности (CSP), недельная проверка ссылок **с российского адреса** (без предупреждений «закрыт для зарубежных адресов»), офлайн-режим и установка как приложение (при наличии домена и HTTPS).

Сервер: Ubuntu 22.04/24.04 с доступом по SSH. Ничего заранее настраивать не нужно: nginx, Node и всё остальное скрипт поставит сам.

## Если на сервере уже есть другие службы (nginx, RustDesk и т. п.)
Установка рассчитана на «чужой» сервер и ничего существующего не меняет:
- Не удаляет и не изменяет сайты nginx (в том числе `default`), `nginx.conf`, часовой пояс. Не перезапускает службы: nginx только **перечитывает** конфигурацию (`reload`, без обрыва соединений) и только после успешной проверки `nginx -t`. При любой ошибке свои файлы убирает и возвращает конфигурацию к исходной.
- Без домена сайт получает **свободный порт 8088–8120** (порт 80 не занимается); с доменом — порт 80 без `default_server`. Порты RustDesk (21115–21119) не затрагиваются.
- `apt` не обновляет установленные пакеты и не перезапускает службы (`--no-upgrade`, `NEEDRESTART_MODE=l`). Node.js берётся системный (если ≥ 18) или скачивается отдельным каталогом без `apt`.
- Правила `ufw` только добавляются (порт сайта), существующие не меняются.
- Недельная проверка ссылок запускается с низким приоритетом (`Nice=19`, не более 20 % процессора и 256 МБ памяти).
- Перед началом сохраняется копия `/etc/nginx` (`/root/posobie-nginx-backup-…tgz`). В конце скрипт сравнивает службы и порты до и после и пишет «без изменений» либо показывает разницу, в том числе по процессам RustDesk.

**Сначала посмотрите, что будет сделано, ничего не меняя:**
```powershell
powershell -ExecutionPolicy Bypass -File .\deploy\ship.ps1 -Target root@IP -Preflight
```
(Если Windows пишет «выполнение сценариев отключено», нужен именно этот вариант с `-ExecutionPolicy Bypass`: политика меняется только на один запуск, системная настройка остаётся прежней.)
Выводится отчёт о сервере (nginx, порты, службы) и план изменений; изменения не вносятся. Затем обычный запуск без `-Preflight`. Порт сайта можно задать самому: `-WebPort 8090`.

## Что нужно на вашем компьютере
- Node.js 18+ (`node -v`), Git.
- Windows 10/11: встроенные `ssh`, `scp`, `tar` (проверка: `ssh -V`). Linux/macOS/Git Bash: то же.
- Папка проекта, например `D:\AI\Posob\test` (`git pull`, чтобы был последний код).

## Выкладка
В PowerShell, из папки проекта:
```powershell
powershell -ExecutionPolicy Bypass -File .\deploy\ship.ps1 -Target root@IP_СЕРВЕРА
```
Linux/macOS/Git Bash: `./deploy/ship.sh root@IP_СЕРВЕРА`.

Скрипт: собирает приложение и прогоняет тесты → упаковывает → отправляет на сервер (**два раза спросит пароль или ключ в вашем окне**, никуда его не сохраняет) → на сервере ставит nginx и Node, раскладывает сайт, включает заголовки безопасности, недельную проверку ссылок, убирает заглушку «404 Not Found», делает самопроверку и первую проверку ссылок. В конце печатает адреса сайта и отчёта.

Повторный запуск той же командой обновляет сайт.

Параметры: `-Port 2222` (нестандартный порт SSH), `-Domain ваш-домен.ru`, `-CertbotEmail почта@…` (выпустить бесплатный HTTPS-сертификат; домен должен уже указывать на IP сервера), `-SkipTests`, `-BundleOnly` (только собрать пакет). У `ship.sh`: `-p`, `-d`, `--certbot почта`, `--skip-tests`, `--bundle-only`.

Если вход не под root, а под пользователем с sudo: `-Target ваш_пользователь@IP`. Установка сама вызовет `sudo`.

## Вход по ключу (без пароля; нужен, если выкладку запускает локальная сессия Claude)
Один раз, в PowerShell (пароль вводите вы, в своём окне):
```powershell
ssh-keygen -t ed25519 -f $env:USERPROFILE\.ssh\posobie_deploy -N '""'
type $env:USERPROFILE\.ssh\posobie_deploy.pub | ssh root@IP_СЕРВЕРА "mkdir -p ~/.ssh && cat >> ~/.ssh/authorized_keys"
```
Затем выкладка без пароля:
```powershell
.\deploy\ship.ps1 -Target root@IP_СЕРВЕРА -Identity $env:USERPROFILE\.ssh\posobie_deploy
```
После работы удалите этот ключ с сервера (строку с комментарием в `~/.ssh/authorized_keys`) и смените пароль.

## Домен и HTTPS
(Если у вас уже есть домен, как `gamma.su`, создайте для сайта отдельный поддомен, например `pomoshnik.gamma.su`: запись **A → IP сервера**. Скрипт перед выпуском сертификата сам проверит, что DNS уже указывает на этот сервер.)

Без домена сайт открывается по `http://IP/`, но **офлайн-режим, установка как приложения и копирование в буфер не работают**: браузеры разрешают их только по HTTPS. Бесплатный сертификат Let's Encrypt выдаётся на домен (`.ru` — около 200 руб./год, запись A на IP сервера). Затем:
```powershell
.\deploy\ship.ps1 -Target root@IP -Domain ваш-домен.ru -CertbotEmail почта@mail.ru
```

## Проверка ссылок
Каждый понедельник в 06:00 по Москве. Отчёт: `http://ваш-сайт/status/links.txt`. Сразу: `systemctl start posobie-links.service`. Остаться должны только страницы, которые просят вход. Отчёт публичный, в нём только адреса из `measures.json`.

### Сертификаты российского УЦ
Часть российских сайтов (например, mosgorzdrav.ru) использует сертификат Минцифры, которого нет у Node. Установщик скачивает корневой и промежуточный сертификаты с gu-st.ru в `/opt/posobie-tools/certs/russian-ca.pem`, печатает их отпечатки (сверьте с https://www.gosuslugi.ru/crt) и подключает **только** к проверке ссылок через `NODE_EXTRA_CA_CERTS`. В системное хранилище, nginx и браузеры они не попадают. Отключить: `RU_CA=0`. Если скачать не удалось, такие ссылки остаются предупреждениями.

## Безопасность
Что уже сделано в сборке и конфигурации:
- Сайт статический: нет серверного кода, базы, форм и загрузок; разрешены только GET и HEAD (остальное — 405).
- Строгая CSP (только свои скрипты, шрифты и запросы; фреймы и `object` запрещены), `nosniff`, `X-Frame-Options`, COOP/CORP, HSTS при HTTPS. Нет `eval` и `innerHTML`; внешние ссылки открываются с `noopener noreferrer`, а в данных допустимы только https.
- Ограничение частоты запросов (10 в секунду с адреса, всплеск 80), короткие таймауты, скрытые файлы закрыты, версия nginx скрыта.
- Ответы из файла или кода проходят проверку: остаются только известные вопросы с допустимыми значениями.
- Параметры `-Domain`, `-CertbotEmail`, `-Port` проверяются до подстановки в команды и конфигурацию.
- Проверка ссылок работает под `www-data` с `NoNewPrivileges`, `ProtectSystem=strict`, `ProtectHome`.

Что делает владелец сервера (скрипты этого не меняют, чтобы не отрезать вам доступ): `sudo bash deploy/audit-server.sh posob.gamma.su` — отчёт только для чтения, что ещё усилить (SSH по ключам, ufw, fail2ban, автообновления, продление сертификата).

- Сайт статический: нет баз данных, форм отправки и личных данных на сервере. Ответы остаются в браузере пользователя.
- Чтобы не работать под root: создайте пользователя с sudo и вход по ключу (`ssh-copy-id`), затем отключите вход по паролю (`PasswordAuthentication no` в `/etc/ssh/sshd_config`), включите `ufw allow OpenSSH` и `ufw enable`.
- Обновляйте систему: `apt update && apt upgrade`; автообновления безопасности: `apt install unattended-upgrades`.
- Пароль, ключи и токены **не присылайте в чат и не добавляйте в репозиторий**. Скрипты ничего из этого не хранят.

## Состав
- `ship.ps1`, `ship.sh` — запуск с вашего компьютера.
- `install-bundle.sh` — выполняется на сервере (его запускает `ship`).
- `nginx-posobie.conf`, `posobie-headers.conf` — сайт и заголовки (CSP, nosniff и др.).
- `posobie-links.service`, `posobie-links.timer` — недельная проверка.
