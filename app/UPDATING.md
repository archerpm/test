# Как обновлять данные сервиса

Все правила, суммы и ссылки лежат в `src/data/`. Код менять не нужно.

## Раз в год (индексация)
1. **Суммы** — `src/data/amounts.json`: поменяйте `value`, `validFrom`, `source`. Названия мер и вопросов подставляют суммы сами (`{{care_fed}}` и т. п.). Затем обновите `_meta.nextReview` на следующую дату.
   - 1 февраля: ЕДВ, выплата по уходу (постановление Правительства РФ об индексации).
   - 1 апреля: социальная пенсия по инвалидности.
   - Декабрь: постановление Правительства Москвы о размерах выплат на следующий год (московская выплата по уходу, доплата к пенсии).
   - Прожиточный минимум Москвы, лимиты вычетов — по новым актам.
2. Проверьте нормы, на которые ссылаются меры (`basis`), и поставьте новую `checkedAt` в `measures.json` только тем мерам, которые перепроверили по первоисточнику.
3. `npm test` и `npm run check:fresh`.

## Новая мера или изменение условий
1. Подтвердите норму по первоисточнику и обновите `../DOCUMENTS.md` / `../RESEARCH.md`.
2. `src/data/measures.json`: условия (`eligibility`, последнее правило без `when`), документы, сроки, ссылки (`apply` с `kind: "apply"` для онлайн-подачи и `"info"` для описания), `plan` (приоритет и шаг плана), при необходимости `form` (памятка подачи).
3. Если мера использует новый вопрос — добавьте его в `questions.json` с `short` (короткое название для объяснений) и пояснением `help`; вопросы-ветвления помечайте `noUnknown: true`.
4. Новый общий документ — в `documents.json` (`match` — подстроки, по которым документ узнаётся в списках мер). Новое сокращение — в `glossary.json`.
5. Тест в `src/engine.test.ts` или `src/features.test.ts`.

## Проверки
- `npm test` — правила, суммы, документы, план, сохранение.
- `npm run test:e2e` — прохождение опроса, формы, доступность (axe), офлайн (нужен `npm run preview` и `npx playwright install chromium`).
- `npm run check:links` — ссылки (404/410 — ошибка; закрытые сайты и вход — предупреждения). Запускается автоматически по понедельникам (`.github/workflows/links.yml`).
- `npm run check:fresh` — сведения старше 90 дней и пропущенная дата пересмотра сумм (при `STRICT=1` — ошибка).

## Публикация (GitHub Pages)
1. В репозитории: Settings → Pages → Source: **GitHub Actions**.
2. Слейте ветку в `main`: workflow `pages.yml` соберёт и опубликует `app/dist`.
3. Приложение работает офлайн после первого открытия (сервис-воркер) и устанавливается на телефон как приложение.
